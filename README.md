# 사진 다이어리 (PWA)

여행·나들이 사진을 **날짜별로 묶어서** "누구와 · 어디서 · 뭐 먹었는지"와 함께 남기는 앱입니다.
혼자 보는 앱이라 **로그인도 서버도 없고**, 사진과 기록은 이 휴대폰 브라우저 안(IndexedDB)에만 저장됩니다.

## 바로 쓰기

**https://tanya409448-star.github.io/photo-diary/**

1. 위 주소를 휴대폰 크롬에서 엽니다.
2. 오른쪽 위 **메뉴(점 세 개) → 홈 화면에 추가**.
   아이폰은 사파리에서 **공유 → 홈 화면에 추가**.
3. 홈 화면 아이콘으로 열면 주소창 없이 앱처럼 열립니다.
4. 한 번 열어 두면 인터넷이 없어도 앱이 열립니다(사진·기록은 원래 기기 안에 있음).

## 업데이트 (2026-11-26 · 앱 v1.1.0)

안드로이드에서 **촬영**을 누르면 "메모리가 부족하여 이전 작업을 완료할 수 없습니다"가 뜨고 달력으로 튕기던 문제를 고쳤습니다.

- **앱 안 카메라**: `촬영`이 외부 카메라 앱 대신 앱 안에서 미리보기 + 촬영 버튼을 엽니다(`getUserMedia`).
  찍은 사진은 최대 변 1600px JPEG로 저장하고 **카메라 스트림을 바로 끊습니다**. 앱을 열어 둔 채 찍기 때문에 뒤로 튕기지 않습니다.
- 카메라를 쓸 수 없거나 권한이 거부된 경우에만 안내를 띄우고 예전처럼 휴대폰 카메라 앱을 엽니다.
- **고화소 사진 메모리 최적화**: `불러오기`로 담는 사진도 최대 변 1920px JPEG(품질 0.88)로 줄여 저장합니다(1920px 이하 사진은 원본 그대로).
  썸네일은 `createImageBitmap`의 축소 디코딩을 써서 메모리 피크를 줄였습니다.
- **보던 화면 유지**: 기록 화면 주소가 `#day=2026-11-26`처럼 남아, 앱이 다시 열려도 같은 날짜 기록으로 돌아옵니다.
- 서비스 워커 캐시 이름을 `photo-diary-v2`로 올려 설치된 홈 화면 앱이 새 버전을 바로 받아옵니다.

- 주 사용 환경: **안드로이드 크롬** (모바일 우선, 세로 화면)
- 만든 형태: 빌드 도구 없는 단일 HTML + CSS + JS 파일 (프레임워크 없음)

## 파일 구성

```
├── index.html              앱 전체 (화면·스타일·로직이 모두 들어 있음)
├── manifest.webmanifest    PWA 매니페스트 (이름·아이콘·standalone)
├── sw.js                   서비스 워커 (앱 껍데기 오프라인 캐시)
├── icon-192.png            홈 화면 아이콘
├── icon-512.png            홈 화면 아이콘 (maskable 겸용)
└── README.md
```

모든 경로가 상대 경로(`./`)여서 `https://<계정>.github.io/photo-diary/` 같은 서브패스에서도 그대로 동작합니다
(`manifest.webmanifest`의 `start_url: ./index.html`, `scope: ./`, `sw.js`의 `navigator.serviceWorker.register('sw.js')`).

## 화면과 기능

### 1) 달력 (기본 탭)
- 월 달력, `‹ ›`로 달 이동, **오늘** 버튼.
- 기록이나 사진이 있는 날짜에 **점** 표시(사진이 있으면 테라코타, 글만 있으면 올리브).
- 날짜를 누르면 그날 기록 화면이 열립니다. **비어 있는 날짜도 바로 열려서** 기록할 수 있습니다.
- 달력 아래 **최근 기록** 카드 4개 (날짜 · 장소/제목 · 사진 썸네일 1장).
- 첫 실행(데이터 없음)에는 안내 카드와 `오늘 기록 시작` 버튼이 나옵니다.

### 2) 기록 화면 (달력에서 진입)
- 상단에 `2026년 11월 26일 목요일` 형식 날짜와 `오늘 · 사진 3장` 요약.
- 사진: 썸네일 그리드(2열, 넓은 화면 3열), **촬영**(앱 안 카메라)과 **불러오기(여러 장)** 두 버튼.  - 사진마다 `◀ ▶`로 순서 변경, `✕`로 삭제(확인 창).
  - 사진을 누르면 전체 화면 라이트박스(좌우 스와이프, 이전/다음 버튼, ESC).
- 입력: 제목(선택) · **누구와**(이전에 입력한 이름이 자동완성 칩으로) · **장소**(이전 장소 칩) ·
  **뭐 먹었어요** · 메모(여러 줄) · 별점(0~5, 같은 별을 다시 누르면 0).
- 입력하면 **0.4초 뒤 자동 저장**되고 오른쪽 위에 `저장됨`이 표시됩니다.
  뒤로 가기·탭 전환·앱 전환 시에도 대기 중인 저장을 바로 반영합니다.

### 3) 갤러리 탭
- 모든 사진을 **최신 날짜순**으로 묶어서 표시(하루 5장이 넘으면 `n장 더보기`).
- 상단에 **사람별 / 장소별 필터 칩**(기록에서 자동 생성, 둘 다 선택 가능).
- 사진을 누르면 라이트박스에 날짜·장소·사람·뭐 먹었는지 캡션이 함께 나옵니다.

### 4) 검색 탭
- 제목 · 사람 · 장소 · 음식 · 메모를 한 번에 **부분 일치** 검색.
- 결과 카드: 날짜, 장소, 사진 썸네일, 메모 요약. 카드를 누르면 그날 기록으로 이동합니다.

### 5) 설정 (달력·갤러리 오른쪽 위)
- **전체 내보내기**: 모든 기록 + 사진 원본(base64)을 `다이어리-백업-YYYYMMDD.json` 하나로 저장.
- **가져오기**: 같은 파일을 고르면 지금 기록에 **병합**(이미 있는 날짜·사진 id는 건너뜀).
- 홈 화면 추가 안내, 저장 위치 안내.

## 저장 구조 (IndexedDB `photo-diary`, 버전 1)

| 저장소 | 키 | 내용 |
|---|---|---|
| `days` | `date` (`YYYY-MM-DD`) | `{date, title, people, place, food, memo, rating, createdAt, updatedAt}` |
| `photos` | `id` (autoIncrement) | `{id, date, blob(원본 File), thumb(480px JPEG), order, caption}` + 색인 `by-date` |
| `photoIndex` | `id` | `{id, date, order, caption, thumb}` — 목록·갤러리용 사본(원본 blob 없음) + 색인 `by-date` |

- **`photoIndex`를 따로 둔 이유**: 앱을 열 때 원본 사진을 전부 읽으면 수백 MB를 매번 읽게 됩니다.
  목록에 필요한 정보(날짜·순서·썸네일)만 담은 작은 저장소를 함께 두고, **원본은 라이트박스·내보내기에서만** 읽습니다.
  사진 추가·삭제·순서 변경은 두 저장소에 **한 트랜잭션으로** 반영해 어긋나지 않습니다.
- 썸네일은 `canvas`로 **긴 변 480px, JPEG 품질 0.82**. 화면 표시는 항상 썸네일이고, 원본은 크게 볼 때만 씁니다.
- 저장 사진: **최대 변 1920px, JPEG 품질 0.88**로 줄여서 저장합니다(1920px 이하 사진은 원본 `File` 그대로).
  이 축소는 디코딩 단계에서(`createImageBitmap`의 `resizeWidth`/`resizeHeight`) 이뤄져 모바일 브라우저 메모리를 적게 씁니다.
- 기록 화면 주소는 `#day=YYYY-MM-DD`를 유지합니다(새로고침·재시작해도 보던 날짜로 복귀, 뒤로 가면 해시 제거).

## 백업에 대해 꼭 알아 둘 점

- 기록과 사진은 **이 브라우저의 사이트 데이터**입니다. 브라우저에서 "인터넷 사용 기록 삭제 → 사이트 데이터"를 지우거나
  앱을 삭제하면 함께 사라집니다. 기기를 바꿀 때도 자동으로 넘어가지 않습니다.
- 그래서 **가끔 설정 → 전체 내보내기**로 JSON을 만들어 두는 것이 유일한 백업 수단입니다.
  사진 원본이 들어가서 파일이 커질 수 있습니다(사진 100장이면 수십 MB).
- 아이폰 사파리는 7일 이상 쓰지 않은 사이트의 저장소를 지울 수 있습니다(ITP). 백업을 주기적으로 하세요.
- **주소가 달라지면 저장된 데이터는 이어지지 않습니다**(브라우저는 주소별로 데이터를 나눠 둡니다).

## 개발 메모

- **파일을 고친 뒤에는 `sw.js`의 `CACHE_VERSION`을 올리세요**(`photo-diary-v2` → `v3`).
  그래야 이미 설치된 홈 화면 앱이 새 파일을 받습니다. (페이지 이동 요청은 네트워크 우선이라 인터넷이 있으면 바로 반영되고,
  오프라인일 때만 캐시를 씁니다.)
- 진단용으로 `window.__diary`(상태·날짜 함수)를 노출해 두었습니다. 사용 기능에는 영향이 없습니다.
- 배포: `main` 브랜치 루트를 GitHub Pages로 서비스합니다. 고친 파일을 `main`에 올리면 1분 안팎 뒤 반영됩니다.

## 검증 상태

### 실제로 확인한 것 (헤드리스 Chromium, 390×844 모바일 뷰포트, 한국 시간대)
- 달력 표시·월 이동·오늘 버튼, 날짜 점 표시, 빈 날짜 진입, 최근 기록 카드
- 사진 여러 장 담기(불러오기/촬영), IndexedDB 저장, 고화소는 1920px로 축소·작은 사진은 원본 유지, 썸네일 480px·JPEG·원본보다 작음
- 앱 안 카메라: 1920×1080 가짜 카메라 입력으로 미리보기 → 촬영 → **1600×900로 저장** → 모달·스트림 즉시 해제
- 카메라 권한 거부/미지원 시 안내 후 휴대폰 카메라(`capture`) 폴백
- `#day=2026-11-26` 해시로 새로고침해도 기록 화면·입력값·사진 유지, 뒤로 가면 달력과 해시 제거
- 서비스 워커 캐시 `photo-diary-v2` 생성, 옛 `v1` 캐시 삭제, 오프라인 실행
- 자동 저장(디바운스 0.4초)과 `저장됨` 표시, **입력 직후 뒤로 가도 저장됨**, 새로고침 후 값·순서 유지
- 순서 변경(◀ ▶)과 저장, 사진 삭제(확인/취소), 사진·글이 모두 비면 날짜 기록 삭제
- 라이트박스: 열기, 캡션(날짜·장소·사람·음식), 키보드·**터치 스와이프** 이동, ESC 닫기, 원본 이미지 로드
- 갤러리: 날짜 그룹, 사람/장소 필터, 5장 넘으면 더보기, 라이트박스 연결
- 검색: 음식·사람·메모 부분 일치, 결과 없음 안내, 결과에서 기록 열기, 돌아오면 검색어 유지
- 자동완성 칩(사람·장소), 별점 저장/해제
- 내보내기: 파일명 규칙, JSON 구조(base64 원본 포함), 다시 가져오면 중복 건너뜀, DB를 비운 뒤 복원하면 기록·사진 전부 복구
- 깨진 JSON은 안내 후 거부하고 데이터를 건드리지 않음
- 서비스 워커 등록·캐시, **오프라인 새로고침에도 앱이 열리고 기록이 보임**, 매니페스트·아이콘 응답 200
- 다크 모드(`prefers-color-scheme: dark`) 전환
- 5000×3500 대용량 사진도 480px 썸네일 생성(0.2초)
- 콘솔 오류 없음

### 확인하지 못한 것
- **실제 안드로이드 크롬·아이폰 사파리 실기기**에서의 동작(홈 화면 추가, 실제 카메라 권한 창, 실제 사진 EXIF 회전).
  헤드리스 크롬의 가짜 카메라로는 `getUserMedia` 경로까지 확인했지만, 실기기의 카메라 앱·메모리 동작은 직접 열어 봐야 합니다.
- 사진 수백~수천 장을 쌓았을 때의 체감 속도와 저장 용량 한도(브라우저 할당량).
- iOS에서의 라이트박스 스와이프 감도.

### 알려진 한계
- **HEIC 사진**은 크롬이 미리보기를 만들지 못해 "미리보기를 만들 수 없는 사진" 타일로 저장됩니다(원본은 보존).
- 한 번에 수십 장씩 담으면 처리에 시간이 걸립니다(진행 표시는 뜸).
- 내보내기 파일은 전부 메모리에 올려서 만듭니다. 사진이 아주 많으면(수백 MB) 실패할 수 있습니다.
